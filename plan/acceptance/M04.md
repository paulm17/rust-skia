## Production fixes during acceptance

None. The disputed `RRectPriv::are_rect_and_radii_valid` behavior was checked against pinned `src/core/SkRRect.cpp`: `are_radii_predicates_valid` deliberately accepts `sum <= limit` as well as sums within `SkScalarNearlyEqual` or four-ULP `AlmostEquals` of the limit. The Rust implementation matches that tolerance. The initial supplemental expectation was therefore wrong, not the production code.

Pinned C++ reference confirms all other checked behavior:

- `MakeILarge`, `MakeLargeS32` and `MakeLargest` are nonempty; both inverted variants are empty.
- `setBoundsCheck` returns true and an empty rect for an empty point span; one point yields the degenerate rect; Inf/NaN fail and leave an empty rect. `setBoundsNoCheck` leaves all-NaN on failure.
- `whOverflow` has non-finite width/height and finite center/half extents.
- `Rect_subtract`, subtract-overflow and closest-disjoint-edge outputs match.
- Point3 GRec lengths, overflow normalization, `Size::toRound`, and the scale-to-sides adjustment sequence match.
- RRect fuzzer reads return 48; b511 set operations are valid; the b527 offset oval remains valid and oval.

## Test-source corrections outside acceptance

1. **Initial compile blocker — first fuzzer buffer.** The supplied `tests/m04/rrect.rs` contained 28 occurrences of `0x7f32` where pinned `RoundRectTest.cpp` contains `0x7f`; `0x7f32` does not fit `u8`. The test owner restored all 28 fixture bytes to `0x7f`. The corrected fixture now matches the pinned C++ input exactly.
2. **Initial wrong assertion — `tests/m04/supplemental.rs:147`.** It required a radius one ULP above 50.0 to be invalid. Both pinned C++ and Rust accept it (`excess.x=50.0000038`, `bits=0x42480001`; `AreRectAndRadiiValid(excess)=1`). The test owner now accepts the one-ULP case and retains rejection coverage with a clear 51.0 overlap.
3. **Non-semantic formatting.** The supplied test modules were not rustfmt-normalized. Deepseek applied `cargo fmt --all`; only the six `tests/m04/*.rs` modules changed. No assertion, expected value, tolerance, fixture or exclusion changed. Before/after hashes are in `tests-before-format.sha256`, `tests-after-format.sha256` and `tests-format-changes.log`.
