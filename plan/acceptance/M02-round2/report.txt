### Corrections to Codex test/tool sources

These changes correct test interfaces and strengthen evidence collection; no expected value, tolerance, input, exclusion or existing failure assertion was relaxed.

1. The old polymorphic probe's local test named `sk_make_sp` shadowed the imported factory. The helper now explicitly uses Deepseek's documented `rust_skia::sk_make_sp_as::<dyn Abstract, _>` to return an abstract owning handle. Both API compilation and the original zero-assertion `sk_make_sp` registration pass. This validates the reached construction/drop helper, **not** arbitrary erasure safety, virtual access or convertible smart-pointer copy/move behavior.
2. The two-argument `SkTaskGroup::add` probe now calls the documented `add_priority` method. Rust has no overloads for the two earlier call shapes. This fixes the probe spelling only; it does not establish executor binding, priorities or concurrency.
3. The Rust isolation runner previously chose the last Cargo JSON executable, which can be the application binary when artifact ordering changes. It now requires target name `m02_test`, target kind `test`, and test profile, then reconciles the exact 107-original name set and all 118 discovered cases. Both profiles were rerun after this correction; an empty or partial discovery now fails the runner.
4. Seventeen previously unexecuted registrations are now complete executable translations: the remaining eight hash cases, Deque, InternalLList, RawPtr_Stl, both container-API template cases, the full String registration, SkTBlockList, copy-on-first-write and the abstract factory helper. The full String and container-API cases fail as recorded below. All prior 90 bodies remain in the run.
