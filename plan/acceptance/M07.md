## Production defects found and fixed during acceptance

The first execution of the supplied tests failed 7 registrations. All seven were production defects; no test file, assertion, expected value, tolerance or fixture was touched.

1. `RRect::transform(&Matrix)` was missing (reported by Codex in `tests/m07/README.md`). Ported the non-legacy `SkRRect::transform` overload (`src/rrect.rs`), including `mapRect`, empty/finite rejection, rect/oval short-cuts and `DeduceRRectFromContour` for general rrects.
2. `SkPathBuilder::addPath` iterated with `SkPathIter`, which trims a trailing `moveTo`. The reference uses `SkPathPriv::Iterate`, i.e. the raw `SkPath::RangeIter`, and yields nothing for a non-finite source. Switched to `RangeIter` with the finiteness guard (`src/sk_path_builder.rs`); this fixed `SkPathBuilder_trailingmove_addpath` and `pathbuilder_addPath`.
3. `Convexicator::IsConcaveBySign` reset the current point for its second pass instead of keeping the last point and rewinding to index 0, so the wrap-around vector was measured from the wrong origin. Fixed (`src/sk_path_priv.rs`); this fixed the `pathbuilder_addPath` convexity case.
4. `SkPathData::make` skipped validation, so invalid verb/point/conic-count combinations were accepted. It now performs `valid_path_data` before `MakeNoCheck`, matching `SkPathData::Make`; `make_checked` delegates to it (`src/sk_path_data.rs`).
5. `SkPathData::polygon` unwrapped the bounds check and panicked on non-finite points. It now returns the error singleton on failure, mirroring the reference's null return in the Arc-based API (`src/sk_path_data.rs`).
6. Path serialization read the fill type from bits 0..1 (the version field) instead of bits 8..9. Fixed (`src/sk_path.rs`); this fixed the v4 fixture comparison.
7. `SkPath::read_from_memory` returned `Some(error_singleton)` when `SkPath::Raw` rejected a payload (bad verb byte, non-finite point, negative conic weight). It now returns `None` with `bytes_read = 0`, mirroring the reference nullopt (`src/sk_path.rs`). Also corrected `SkPath::get_points` to return the number of points written, the `SkPath::getPoints(SkPoint[], int max)` contract the Rust slice API adapts.

All seven fixes are in production code and rerun evidence below covers the final tree.

### Test-source correspondence notes

In the pinned checkout `include/core/SkPathBuilder.h:34-36` **defines** it unconditionally, so the original takes the `setLastPt(0,0)` branch rather than `moveTo(0,0)`. - `data::pathdata_make_nonfinite` expresses the reference's null polygon result as the production error singleton (`Arc::ptr_eq` with `SkPathData::peek_error_singleton()`), which is the documented Arc adaptation and is now produced by a real failure path rather than a panic.
