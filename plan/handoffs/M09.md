### Prerequisites implemented early (recorded ownership transfer)

The inventory assigns `SkRegion_path.cpp`, `SkEdge*`, `SkScan_Path.cpp` and `SkScan_AntiPath.cpp` to M07, but the M07 handoff explicitly deferred the non-antialiased scan converter and `SkRegion_path` to their M14/M09 gates. `SkRegion::setPath`, `SkAAClip::setPath(doAA=false)` and `SkRasterClipStack` reach them, so the non-AA `SkEdge`/`SkBasicEdgeBuilder`/`sk_fill_path`/`walk_edges` path is implemented here instead of behind a stub. No M07 production behavior changed, and all M01–M08 tests still pass unchanged.

### Adaptation notes

- **Ownership.** Reference `SkRegion` uses an intrusive `SkRefCnt` `RunHead`; the port stores the identical run data (`bounds`, `ySpanCount`, `intervalCount`, `runs: Vec<i32>`) in an `Arc`, preserving copy-on-write sharing (`Arc::ptr_eq` fast path in equality). `SkAAClip` uses the same scheme for its y-offset table plus packed run bytes. `SkClipStack` keeps elements in a `Vec` instead of an `SkDeque` of placement-new'd objects; ordering and both iterator directions are unchanged.
- **Layout/serialization.** `SkRegion::write_to_memory`/`read_from_memory` reproduce the reference's little-endian byte stream (int32 run count, bounds, optional y-span/interval counts and runs) and its validation/error paths (returns 0 on truncated or invalid input). The exact bytes were compared against the reference for empty, rect and complex regions.
- **RTree storage.** `Node*`/`Branch` become indices into a `Vec<Node>` plus `BranchData::{Subtree, OpIndex}`; because `Vec` growth would otherwise move nodes, subtrees are addressed by index. Bulk-load grouping, node capacity constants and traversal order are unchanged, so `search` reports the same indices in the same order.
- **Clip shader.** `sk_sp<SkShader>` does not exist until M13, so `SkClipStack`/`SkRasterClip` hold an opaque `SkShaderHandle`; `ClipShader` records the reference's structural blend composition. `clipShader`/`op_shader` keep their observable stack/state effects today and can materialize the shader at M13 without changing these APIs.
- **`SkClipStackDevice`.** The reference derives from `SkDevice`; M14 owns `SkDevice`. The port carries the image bounds, `localToDevice`, `globalToDevice` and device origin as fields, and every override keeps the reference body. `clipRegion` builds the device-space boundary path and translates by the origin, exactly as the reference does.
- **`clipRegion`/`android_utils_clipAsRgn`.** Both use `SkRegion::add_boundary_path` and `SkRegion::set_path`, which are real implementations (not shortcuts); the differential matched complex region stacks.
- **`getBounds` overloads.** The reference's `getBounds(bounds, type, isIntersectionOfRects)` is exposed as `get_bounds_with_intersection`; the two-argument form is `get_bounds`. `getConservativeBounds` takes `Option<&mut bool>`, the `nullptr` case.
- **`SkClipStack_AsPath`.** Returns `Option<SkPath>`; `None` means “this stack needs `SkPathOps`” (M23) and is never a fabricated path. This constant is unreachable from any M09 registration; the only callers in the reference are PDF/XPS (M27).
- **Debug-only members.** `SkClipStack::dump`, `SkAAClip::validate`/`debug` and `SkRasterClip::validate` live behind `SK_DEBUG` in the reference and are not part of the Rust release API. `SkRasterClipStack::validate` is implemented and debug-asserts the same invariants. The `SK_DEBUG` assertions that guard observable behavior are preserved as `debug_assert!`.
- **Supersampling bounds.** `SkAAClip::setPath(doAA=true)` scales the path by 4 and scan-converts it into a region clipped to the AAClip bounds. Unlike the reference's RLE blitter, it has no 16-bit index or 32767-coordinate constraint, so the reference's “too large for AA” fallback is not observable in this representation.

The AA-clip circle test differs from the reference by roughly one tenth of one percent because AA coverage is currently 4×4 supersampled instead of the reference's exact analytic area coverage:

| Label | Reference | Rust |
| --- | --- | --- |
| `aa.circle.sum` (sum of mask bytes) | 1999853 | 2002004 |
| `aa.combined.sum` | 1999853 | 2002004 |
| `aa.diff.sum` | 1591853 | 1594004 |

The cause is the deferred `SkScan::AAAFillPath`/`SkAnalyticEdge` port; both are M14-owned in the inventory and M14's `AAClipTest` is the gate that asserts exact AA parity. This is recorded as an open required branch, not as complete.
