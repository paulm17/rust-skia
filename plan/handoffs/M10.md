### Early ownership transfer

`SkAlphaType` is assigned to M11, but `SkColorSpaceXformSteps` (M10) and `SkRGBA4f::premul/unpremul`
take it by value. `src/sk_alpha_type.rs` implements it now (`SkAlphaType::{Unknown, Opaque, Premul,
Unpremul}`, `K_LAST_ENUM`, `from_i32`/`to_i32` helpers). No M11 behavior is pre-empted; M11 only needs
to attach its own tests.

### Excluded kernels

`skcms_TransformHsw.cc` and `skcms_TransformSkx.cc` only define `run_program` for SSE4.1/AVX-512
targets (`SKCMS_TARGET_HSW`/`SKCMS_TARGET_SKX`). `MACOS-SCOPE.md` excludes Intel/x86_64
implementation, so they have no arm64 consumer. The reference checkout's own arm64 build also
compiles only `skcms_TransformBaseline.cc`. This is a scope exclusion, not an unfinished branch.

### Adaptation notes

- **Ownership.** `sk_sp<SkColorSpace>` becomes `Arc<SkColorSpace>`-equivalent by value/clone; the
  reference's singleton `SkColorSpace_Base` objects are `OnceLock` singletons here. `sk_sp<SkData>`
  retention in `ICCProfileChromium` is replaced by an owned parsed profile.
- **`SkRGBA4f`.** A single generic `SkRGBA4f<T>` covers `SkColor4f` and `SkPMColor4f`; the reference's
  `SkColor4f::FromColor`/`ToSkColor` are `from_color`/`to_sk_color`, and `fitsInBytes`/`toBytes_RGBA`
  keep the same round-half-to-even behaviour.
- **Colour table storage.** The reference stores its four tables in one 256×4 `A8` `SkBitmap`. M11
  owns `SkBitmap`, so the port stores four `[u8; 256]` arrays; `flatten_bytes` reproduces the
  reference byte stream exactly and `deserialize` validates its length.
- **Serialization.** `SkColorSpace::write_to_memory`/`serialize`/`deserialize` operate on byte
  buffers. The `SkWriteBuffer`/`SkReadBuffer` bridges (including `SkColorTable::Deserialize`) are
  **M22**; the byte format, version field and tag order are the reference's.
- **ICC parsing.** `skcms_Parse` reads the raw ICC byte stream with the reference's tag-offset
  validation, `gather_24`/`gather_48` slack requirements, `K_MAX_TABLE_ENTRIES` and
  `SKCMS_MAX_GRID_POINTS` limits, and reproduces both A2B and B2A structures. 16-bit curve/CLUT
  entries are byte-swapped **once during parsing** into native `u16` (`SkcmsCurveTable::U16`,
  `SkcmsGrid::U16`); the reference swaps at sampling time because it points into the raw buffer.
  Sampling therefore uses `f_from_u16` directly. This was the cause of the A2B mismatch recorded
  below and is now fixed.
- **Transform pipeline.** The reference builds an `Op` array and runs a templated kernel with
  `N = 1/4` vectorization. The port builds the same op list and interprets it per pixel in `f32`.
  Op order, `SKCMS_MAX_PROGRAM_OPS` truncation, alpha handling, `swap_rb` placement, gray-destination
  profile substitution (XYZD50 identity + Y transfer function) and CMYK inversion follow the
  reference. Profile identity is decided by `std::ptr::eq`, like the reference's pointer compare.
- **`r/g/b/a` for A8/G8/GA88 and 1-channel A2B.** The port keeps the reference's channel aliasing
  (loads write all of `r,g,b`, and a 1-input CLUT uses `r`), so gray ICC profiles transform through
  the same program the reference builds.

### Development differential (Deepseek-authored, **not** acceptance evidence)

All artifacts are in the git-ignored `target/m10-ref/` directory; see its `README.md` for the exact
build lines.

1. **ICC profile parsing (11/11 files exact).** Every file under
   `skia/resources/icc_profiles/*.icc` was parsed by both `skcms_Parse` and `skcms_parse`, printing
   colour space, PCS, tag count, TRC entries/parametric values, XYZD50 matrix, A2B/B2A channel
   counts and the input-channel count. All printed values matched; the only textual difference was
   float formatting (`%.9f` vs `{:.9}`). Includes `AdobeRGB1998`, `HP_Z32x`, `HP_ZR30w`, `apng19`,
   `pq_hdr`, `mu_gray`, `srgb_lab_pcs`, `sRGB_FT_LUT_ab`, `sRGB_FT_LUT_lab`, `DisplayP3`, `crbug_`.
2. **Transform matrix (1,240/1,368 observations byte-identical).** 12 profile pairs × 39 pixel
   formats × 3 alpha formats, `nz = 4`: `srgb↔linear`, `adobe↔srgb`, `pq↔srgb`, `apng19↔srgb`
   (A2B source and B2A destination), `gray↔srgb`, `lab_pcs→srgb`, plus each format's identity
   round-trip into itself. The A2B/CLUT rows first differed; the native-vs-big-endian U16 sampling
   fix (see “ICC parsing” above) brought them to byte equality.
3. **Remaining 128/1,368 differing lines** (see “Known deviations”): 6 ABGR/ARGB_4444 identity rows,
   2 `RGBA_hhhh` premultiplied rows, and 120 rows that feed out-of-domain 10-bit codes into
   `RGB(A)_101010x_XR`. A separate valid-domain XR check (codes 384–889, 8 observations) is
   byte-identical, confirming the port's XR arithmetic.
4. **Defect found and fixed by the differential:** `classify_into` filled its `Pqish`/`Hlgish`
   out-params only when the caller passed `Some(..)`. `skcms_transfer_function_eval` and
   `skcms_transfer_function_invert` passed `None` and then `unwrap()`ed, panicking on PQ/HLG-ish
   transfer functions. The out-params are now always written, matching the reference's non-null
   pointer contract.

  The four `ColorPriv`/`ColorTest` tests use integer pixel arithmetic only; `ColorToHSVRoundTrip`

  `sk_parse_find_named_color`; `SkColor4f_FromColor` uses `SkColor4f::from_color` +
  channel comparison.
- **Known deviations (none reachable from the M10 registrations):**
  - `ABGR_4444`/`ARGB_4444` **store**: the Rust port writes the declared nibble packing
    (`r<<12 | g<<8 | b<<4 | a`), so `0x400b → 0x400b`. The pinned reference's `store_4444`
    emits non-round-tripping bytes for the same call (observed `0x400b → 0x320b`, and
    `RGBA_8888 (0x44,0,0,0xbb) → 0x320b`), even when called through
    `out/M09Ref/libskia.a`. Byte parity is therefore not meaningful; 4444 is a deprecated
    format and no M10 registration uses it. Reproduce/close at **M12** when the raster
    pipeline's 4444 handling is compared, or record as NOT_APPLICABLE with this evidence.
  - `RGBA_hhhh`/`RGBA_hhhh_Norm` **premultiplied** conversion: the reference runs the whole
    pipeline in half precision (`F16`) for half-float formats, so a premultiplied round trip
    differs from the port by one low bit in one of four pixels (2/1,368 lines). The port
    computes in `f32` and converts once. This is an arithmetic-width adaptation; no M10
    registration reaches half-float formats. Gate: **M12** (half-float pipeline parity) or
    document as a permanent precision adaptation.
  - 10-bit XR **out-of-domain** inputs: the reference's store sign-extends negative
    intermediates into `0xFFFFFFFF` fields, while the port saturates to 0. Valid-domain XR
    inputs are byte-identical. Gate: **M16/M17** (`ColorSpaceTest.cpp`, `ICCTest.cpp` use
    in-domain XR data).
- **Pending with named gates, none reached by an M10 registration:**
