### Adaptation notes

- **No `SkPaint`.** `SkStroke(const SkPaint&)`, `SkStroke(const SkPaint&, SkScalar)` and `SkStrokeRec(const SkPaint&, …)` read exactly five paint fields. They are expressed as `SkStroke::from_params`, `SkStroke::from_params_and_width`, `SkStrokeRec::from_paint_params` and `SkStrokeRec::from_paint_params_with_paint_style`, which take those five values (`style`, `stroke_width`, `stroke_miter`, `stroke_cap`, `stroke_join`, `res_scale`). When M13 lands the paint-backed overloads can delegate to these without changing behavior. `SkStrokeRec::applyToPaint` and `GetInflationRadius(const SkPaint&, Style)` have no non-paint counterpart; the latter is available as `get_inflation_radius_for_style(SkPaintStyle, …)`.
- **Cap/join procedure identity.** The reference compares `SkStrokerPriv::CapFactory(kButt_Cap) == fCapper`, i.e. function-pointer identity. The port models the three-by-three factory set as `CapProc`/`JoinProc` enums whose variants stand in for the addresses, so `f_capper == CapProc::Butt` keeps the exact reference semantics while every cap/join is still a real call (`CapProc::call`/`JoinProc::call`).
- **Builder-pointer swap in joins.** `MiterJoiner`, `RoundJoiner` and `BluntJoiner` take `SkPathBuilder** outer, SkPathBuilder** inner` and may swap them. The Rust signature is `&mut &mut SkPathBuilder`, which reproduces the swap.
- **`DashInfo::fIntervals`.** C++ returns `SkSpan<const SkScalar>` into the effect's own storage; the port returns an owned `Vec<Scalar>` copy with the same values and length. `as_a_dash()` is `Option<DashInfo>`, matching `std::optional`.
- **`PointData`.** The reference owns `SkPoint* fPoints` (`new[]`) plus `fNumPoints`; the port owns `Vec<Point>` and keeps `f_num_points` in sync, so `points()` yields the same slice. The remaining fields (`f_flags`, `f_size`, `f_clip_rect`, `f_path`, `f_first`, `f_last`) keep their reference meaning.
- **`SkPathEffect` ownership.** `SkPathEffect` holds `Arc<dyn SkPathEffectBase>`; `SkPathEffect::from_base(effect)` is the Rust spelling of `sk_sp<SkPathEffect>(new Impl(...))`, and `base()` is `as_PEB`. `MakeSum`/`MakeCompose` take `Option<SkPathEffect>` (the `sk_sp` null case) and return `Option<SkPathEffect>`.
- **`SkStrokeRec` layout.** The reference packs `fCap : 16`, `fJoin : 15`, `fStrokeAndFill : 1` into one `uint32_t` inside `SK_BEGIN_REQUIRE_DENSE`. The port keeps the identical packed `u32` with the same field order and masks, so the type stays 16 bytes with no padding (`#[repr(C)]`).
- **`SkPathStroker::done`.** C++ does `*dst = fOuter; fOuter.reset();` (`detach`-style value copy). The port uses `*dst = std::mem::take(&mut self.f_outer); self.f_outer.reset();` — the same observable state, since `SkPathBuilder::detach` already resets the builder.
- **`SkPathMeasure` reuse.** Dash, discrete, 1D and 2D effects measure contours through the accepted M07 `SkPathMeasure`/`SkContourMeasureIter`, exactly as the reference does through `SkPathMeasure`. `SkDashPath::SpecialLineRec::init` calls `rec->setFillStyle()` and produces the pre-stroked polygon; that mutation of the output `SkStrokeRec` is observable and implemented.
- **`SkStrokeRec::setResScale` / `SkStroke::setResScale`** keep the reference `SkASSERT` as `debug_assert!`, so release builds accept the same inputs.
- **`SkPath2DPathEffect`/`SkLine2DPathEffect`** keep the reference `!(width >= 0)` validation verbatim (NaN is rejected); the clippy `neg_cmp_op_on_partial_ord` lint is explicitly allowed there with a comment rather than rewriting the comparison.
- **`LCGRandom` seed mixing** is written as `seed.rotate_right(16)` with the reference expression `(seed << 16) | (seed >> 16)` in a comment; the two are identical for `u32`.
- **Constant names** are preserved for numeric behavior: `K_RECURSIVE_LIMITS = [15, 24, 16, 16]`, `K_MAX_DASH_COUNT = 1000000`, `K_STROKE_REC_FILL_STYLE_WIDTH = -1`, `CUBIC_ARC_FACTOR`, `K_ONE_OVER_SQRT2 = 0.707106781f` (`SCALAR_ROOT2_OVER2`), `MAX_REASONABLE_ITERATIONS = 100000`, the point flags `0x01/0x02/0x04`.
- **Float evaluation order** is preserved verbatim in the stroker tolerance tests (`fInvResScale = 1/(resScale*4)`, `fInvResScaleSquared`, `SK_ScalarNearlyZero * fInvResScale`), the dash phase adjustment (including the `phase == len` correction for crbug.com/124652) and the dash/2D effects' accumulation.

### Development differential (Deepseek-authored, **not** acceptance evidence)

A temporary `tests/dev_m08_scratch.rs` printed verb/point/conic dumps for 105 cases: 84 `SkStrokeRec::apply_to_path` combinations (8 paths × 5 cap/join/width/miter quadrants × resolution scale 1 and 3, plus three stroke-and-fill cases and one inverse-fill path), 3 degenerate stroke cases (zero-length line with round and square caps, move+close), the `asADash`/`Make` validation results, and the filtered output of dash, trim, corner, discrete, 1D and 2D effects (18 cases). The same dump program (`target/m08-ref/ref_m08.cpp`, 235 lines, clang++ arm64) was compiled directly against the pinned reference sources (`SkStroke.cpp`, `SkStrokeRec.cpp`, `SkPathEffect.cpp`, `SkDashPath.cpp`, `SkDashPathEffect.cpp`, `SkCornerPathEffect.cpp`, `SkDiscretePathEffect.cpp`, `SkTrimPathEffect.cpp`, `Sk1DPathEffect.cpp`, `Sk2DPathEffect.cpp` and the path/measure translation units they need) and run as a separate process; the two dumps were compared byte-for-byte (`target/m08-ref/diff.txt`).

Result: 3 003 dumped lines, 45 differing lines, all in curved-stroke offset geometry and dash/discrete point coordinates:

- 1-ulp differences on cubic/quad/conic (circle) offset points, e.g. `40482c77` ↔ `40482c78`;
- 1-ulp differences on dash segment endpoints where the phase accumulates (`403b739e` ↔ `403b739d`, `40400001` ↔ `40400000`);
- up to 4-ulp differences on `SkDiscretePathEffect` offsets (`3f44ec44` ↔ `3f44ec40`).

The verb, point and conic **counts**, the contour ordering, every `CASE … applied/style/inflation` header, all `asADash` values (interval lengths, phase `2.0`, negative phase `-7` → `3`), all `Make` validation results and all bounds/mask dumps match exactly. The remaining last-bit spread is float evaluation-order noise inside curve flattening; it is recorded here so Codex does not have to rediscover it, and it is not hidden behind a loosened test. No assigned M08 registration compares stroke geometry — the three `AsADash` cases compare interval values and phase exactly, and those match bit-for-bit. Exact-geometry comparisons of stroked curves (M14 `DashPathEffectTest`, `DrawPathTest`; M23 `StrokerTest`) will need the tolerance those original tests already carry.

The scratch test file was deleted afterwards; `git status` shows no `tests/` change. The reference program and dump logs live only in the ignored `target/m08-ref/` directory.
