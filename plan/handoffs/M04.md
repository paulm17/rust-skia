- Required resources: ordinary CPU only. No GPU, filesystem fixture, or external SDK is required by the assigned M04 registrations.
- Assigned registrations: `Point3` (`tests/Point3Test.cpp:126`); `Rect_largest` (`RectTest.cpp:119`); `Rect_setbounds` (`:133`); `Rect_whOverflow` (`:163`); `Rect_subtract` (`:182`); `Rect_subtract_overflow` (`:255`); `Rect_ClosestDisjointEdge` (`:398`); `RRect_fuzzer_regressions` (`RoundRectTest.cpp:1652`); `RRect_b511391129` (`:1684`); `RRect_b527765132` (`:1714`); `RRect_b547198215` (`:1731`); `ScaleToSides` (`ScaleToSidesTest.cpp:16`); `ISize` (`SizeTest.cpp:12`); `Size` (`SizeTest.cpp:34`).
- Codex translation notes:
  - `SkPoint3::Length(x, y, z)` is available both as `Point3::length_xyz(x, y, z)` and the compatibility alias `Point3::Length(x, y, z)`. Instance length is `point.length()`. Rust cannot have a static `length` and an instance `length` with the same name, so use the aliases above.
  - `Point3::dot`/`cross` are instance methods; `dot_product`/`cross_product` are the static forms. Field access is by value through `x()`/`y()`/`z()`, with `set` for mutation.
  - `RRect` radii are exposed by `radii() -> &[Point; 4]` and `radii_at(Corner)`; corner indices use `Corner::{UpperLeft, UpperRight, LowerRight, LowerLeft}.index()`. `get_type`/`kind` return `Type::{Empty, Rect, Oval, Simple, NinePatch, Complex}`.
  - `RRect::set_rect_radii` takes `&[Point; 4]`, not a raw C++ array pointer. Constructors that take a rectangle use `&Rect`.
  - Serialization uses `write_to_memory(&mut [u8])` / `read_from_memory(&[u8])`; both return 48 or 0. `K_SIZE_IN_MEMORY` is 48. The type tag is not serialized.
  - `RRectPriv` is embedded in `src/rrect.rs`; import it as `rust_skia::RRectPriv`, not from a separate module. `AreRectAndRadiiValid` maps to `RRectPriv::are_rect_and_radii_valid`.
  - `Rect::bounds` returns `Option<Rect>`; `bounds_or_empty` preserves the M01 convenience behavior. `set_bounds_check` returns `bool`; `set_bounds_no_check` writes `SCALAR_NAN` on failure.
  - `RectPriv::subtract`/`subtract_irect` take an out-parameter and return `bool`; use `RectPriv::subtract_value`/`subtract_irect_value` when a value is more convenient. `closest_disjoint_edge` takes two `&IRect` values.
  - `sk_rect_memcpy` is unsafe and accepts raw pointers plus row strides; ensure the source/destination regions follow its documented safety contract in tests.
- Known deviations / deferred behavior:
  - `RRect` transform and conservative-intersection operations are not implemented. They are not required by the M04 registrations and remain for the later path/geometry integration work (M07/M23).
  - C++ debug dump/string helpers for `Rect` and `RRect` are intentionally omitted; they are diagnostic-only and not part of the assigned test contract.
  - `SkRectMemcpy` is exposed as a byte-oriented unsafe function rather than a generic pointer template.
  - RRect type is a Rust enum, so invalid numeric tag values cannot be represented; `read_from_memory` derives the type from the radii instead of accepting a tag.
- No outstanding required M04 behavior is called complete, and no plan amendment is requested. M05 must not begin until Codex acceptance and the user's next handoff.
