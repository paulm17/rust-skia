## Test-readiness and unresolved work

- Ready for Codex to attach and run the M03 registrations listed in the milestone contract. No acceptance result is claimed here.
- Required resources: ordinary CPU only. No GPU, filesystem fixture, or external SDK is required by M03 numeric/random tests.
- Codex translation notes:
  - `SkVx` scalar-left expressions such as `5 == vec` and `max(2, min(vec, 3))` require splats or helper calls in Rust; the vector-right forms and all reductions are available.
  - `Vec<N,T>::Load`/`store` take slices; use slice offsets for C++ pointer arithmetic.
  - `shuffle` is `shuffle(v, [indices...])`; `lo`/`hi`, `xy`/`zw`, and lane access are methods/getters with explicit setters.
  - `SkBitmaskEnum` tests should assert through `SkBitmask::repr`/`contains`/`any`; Rust enums cannot hold undeclared bit patterns.
  - `SkTFitsIn` enum tests must cast enum values to their underlying integer type before calling the generic helpers.
  - `FixedArray::begin/end` map to `iter`/`as_slice`; mutable element access uses indexing or `data_mut`.
  - `SkRandom` is `Clone`/`Debug`; `Default` is the seed-0 constructor.
- Known deviations / deferred behavior:
  - `SkSafeMath::cast_to_i32`/`cast_to_usize` return 0 on failure rather than exposing a static-cast truncation; `ok()` carries the failure contract.
  - `SkTo` panics on invalid conversions in release as well as debug; C++ release builds may rely on static-cast truncation.
  - `SkVx` is scalar-only and does not reproduce `alignas(N*sizeof(T))`. Sizes and lane semantics match. Acceleration/alignment is deferred to M12.
  - YUV uses only the portable low-precision table branch; the debug dump generator is omitted. Consumed by later color/image/GPU work.
  - `SkFloatInterpFunc` remains in `src/scalar.rs` from M01; `SkFloatUtils.h` does not duplicate it.
  - `SkIsPow2` requires an explicit trait implementation for non-primitive integer-like types; all Rust primitive integer types are covered.
- No outstanding required M03 behavior is called complete, and no plan amendment is requested. M04 must not begin until Codex acceptance and the user's next handoff.
